Workflow Navigator

Authentication method

Required scopes:

  • Classic token: repo (private repos) or public_repo (public only).
  • Fine-grained token: Actions: Read on the target repos.

Create one at github.com/settings/tokens. If your org uses SAML SSO, authorise the token for the org after creating it.

The token is stored locally in your browser via chrome.storage.local and is only sent to api.github.com.

Not connected.

Admin setup instructions
  1. Go to GitHub → Settings → Developer settings → OAuth Apps → New OAuth App (or github.com/organizations/<org>/settings/applications for an org-owned app).
  2. Fill in the form:
    FieldValue
    Application nameWorkflow Navigator
    Homepage URLYour org's GitHub URL
    Authorization callback URLCopy the Redirect URL shown above
  3. Click Register application.
  4. Copy the Client ID from the next screen — it is not secret and can be shared with all users. No client secret is needed; this extension uses PKCE.
  5. Share the Client ID with your team. Each user enters it in the OAuth App Client ID field above, saves it, then clicks Sign in with GitHub.

Stable extension ID: the Redirect URL contains the extension's ID. For a published (Web Store) extension the ID is permanent. For a development install it varies unless you pin a key in manifest.json.
